# 三路口 V2I 辅助控速实验

这是 A 驾驶与导航模块的独立延伸。两辆 Lincoln 都使用 A 驾驶代码：对照车只按原导航和当前红灯安全约束行驶；通信车额外使用实际通过 OMNeT++ 6.1／Veins 5.3.1 收到的 RSU 信号相位消息，提前调整速度。

## 场景

- 道路长 280 m，东行两车道，三个相距 70 m 的十字路口。三组灯均为固定 60 s 周期，错峰偏移 0、20、40 s。
- SUMO 负责道路交通和相位，CARLA 负责两辆车的运动；CoBridge 同步两者。CARLA 保留三处实体横向道路和直行连接，去除了当前版本无法稳定加载的转弯连接，因此演示路线只走直行。
- 一个 RSU 位于道路中段，使用现有 Veins 无线模型发 SPaT 消息给通信车。每轮重新加载地图，固定 SUMO、两辆车各自 Traffic Manager 和 OMNeT++ 的随机种子。两车在起点停稳并完成路线规划后，同时释放；随后重置三组灯的初始相位。通信车与对照车交换车道，各运行三轮。
- 两车都使用相同的当前红灯安全限速。未来相位只来自无线消息；消息未送达或过期，通信车退回 A 原有驾驶。障碍、红灯及人工接管仍在 A 的控制链中优先处理。
- SUMO 显示双车；RViz 显示通信车、路线及车上方的无线消息序号和建议速度。

## 运行

已验证环境：WSL Ubuntu、CARLA 0.9.16、SUMO 1.22.0、OMNeT++ 6.1、Veins 5.3.1、ROS 2 Jazzy。本机的一键脚本使用 `/home/wht` 下已安装的软件和 CARLA 启动器。

```bash
cd /home/wht/Autodrive-v2i
# 地图源文件或 SUMO 版本变化后再重建
SUMO_HOME=/home/wht/sumo-1.22.0 /home/wht/carla-venv/bin/python vanet/v2i_glosa/build_map.py
# 图形演示：一轮，包含 SUMO 与 RViz
vanet/v2i_glosa/run_demo.sh --gui --rviz --only-lane 0 --rounds 1
# 完整对照：两种车道分配，各三轮
vanet/v2i_glosa/run_demo.sh --rounds 3
```

运行脚本会连接或启动本机 CARLA。WSL 完全冷启动 CARLA 已在本机验证；首次加载约需数分钟，脚本延后首次查询并重新建立客户端，终端会定期显示等待提示。结束时会清理它创建的 SUMO、桥、车辆、无线进程及 CARLA。结果写到 `vanet/results/v2i_时间/`：`comparison.csv` 为逐轮对照，`comparison.svg` 为四项驾驶指标均值，`lane*/samples.csv` 为轨迹，`radio/omnet/` 记录真实无线发送和接收事件。

## 指标口径

- **停车次数**：行程中车速低于 1 km/h 且前进超过 5 m 后才允许计下一次，避免等灯时低速蠕行重复计数。
- **等待时间**：行程中车速低于 1 km/h 的累计仿真时间。
- **通行时间**：车辆水平速度超过 2 km/h 且前进至少 0.5 m 时开始计时，到驶过第三个停止线后 5 m。不是到完整导航终点的时间。
- **急刹事件**：约半秒内平均减速度超过 4 m/s²，1.5 s 内不重复计数。
- **无线数据**：记录发送、实际送达、送达率及平均空口延迟；对照车不接收消息。
- **安全检查**：检查越过停止线时灯色，并用 CARLA 碰撞传感器记录碰撞。每轮还要求两车导航状态为 `arrived`。

每轮另记录起点坐标、水平及竖直初速、两车实际起步时刻、灯重置时刻、起步灯态及最大横向偏差，用于核对对照条件。对照车也使用实验统一接入的当前红灯安全限速，并非完全未修改的原始 A；两车的区别是只有通信车使用无线获得的未来相位。初速为水平行驶速度，避免把刚生成时的竖直下落误计为行驶。

这些结果只代表本场景和已测试运行。没有设置人为丢包；自然未送达会计入送达率。正式六轮没有混入 NPC，以保持两车对照可复现。

在真实三路口地图上，两种车道分配各三轮，均以相同起点、目标、相位和种子运行：

| 停车次数 | 2.00 | 0.00 |
| 等待时间 | 12.80 s | 0.00 s |
| 三灯通行时间 | 42.17 s | 41.68 s |
| 急刹事件 | 2.83 | 0.00 |
| 闯红灯 / 碰撞 | 0 / 0 | 0 / 0 |

修复起步计时和同步条件后，六轮两车的初始水平速度均近于 0，每轮实际起步时刻完全相同（仿真记录精度 0.05 s）；灯重置到起步均为 1.10 s，起步灯态均为 GrG。两车六轮均报告到达，最大横向偏差约 0.002 m。RSU 向通信车发送 308 条消息，Veins 实际送达 308 条；本次环境中的平均空口延迟约 0.47 ms。通信车平均三灯通行时间缩短约 0.48 s，主要改善是少停车、少等待和少急刹。另用关闭提前控速、但保留相同车辆身份与无线运行的空白对照检查，两车各停车 2 次、等待和通行时间接近。此结果仅适用于这张单一固定配时地图，六轮不是六种独立路况；未测试丢包或不同车流，不做普遍效果的统计推断。

另用 `--npc-count 3 --only-lane 0 --rounds 1` 做了少量 NPC 试跑；这轮不进入正式对照均值。
